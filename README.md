# بكجات — PKGAT

منصة دعوات إلكترونية بباركود دخول. أي شخص يقدر ينشئ حساب، يصمّم دعوة مناسبته،
يولّد باركود فريد لكل مدعو، ويدير الدخول وقت المناسبة من متصفح الجوال — بدون
أي تطبيق.

## المميزات

| | |
|---|---|
| **التصميم** | قوالب جاهزة أو رفع تصميم خاص، مع تحديد موضع اسم المدعو بالسحب، واختيار الخط ولونه من قائمة خطوط تدعم العربية |
| **الباركود** | معرّف UUID عشوائي غير قابل للتخمين لكل مدعو، بحجم ولون وخلفية قابلة للتخصيص مع فحص تباين يحذّر من التركيبات غير القابلة للمسح |
| **المدعوون** | إضافة يدوية، أو لصق قائمة أسماء، أو استيراد Excel/CSV/جهات اتصال — مع تصنيفهم بفئات |
| **التوزيع** | تحميل صور الدعوات فردياً أو كملف ZIP واحد |
| **المسح** | لوحة تعمل من متصفح الجوال عبر كاميرا الجهاز، بحسابات مسح متعددة لكل مدخل |
| **منع التكرار** | كل باركود يُستهلك بعد أول مسح — على مستوى قاعدة البيانات، مع زر تجاوز يدوي مسجَّل |
| **التوقيت** | الباركودات تتفعّل وتنتهي تلقائياً حسب وقت المناسبة، محسوباً على الخادم |
| **التقرير** | نسب الحضور الكاملة وتفصيل حسب الفئة، بصفحة مهيّأة للطباعة/PDF |
| **الدفع** | مُيسّر (مدى، Apple Pay، بطاقات) — دفعة واحدة لكل مناسبة أو اشتراك شهري/سنوي |
| **الأدمن** | إدارة المناسبات والمستخدمين، تعديل كل نصوص الموقع بدون كود، إدارة القوالب ومعرض الأعمال والباقات |

## التقنيات

- **Next.js 15** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS** — نظام تصميم مخصص (أبيض/بيج مع لمسات ملونة)، RTL كامل
- **Supabase** — قاعدة بيانات، مصادقة، تخزين، سياسات RLS
- **Vercel** — الاستضافة

## التشغيل محلياً

```bash
# 1. المتطلبات
npm install

# 2. المتغيرات
cp .env.example .env.local
#    ثم املأ القيم — راجع التعليقات داخل الملف

# 3. قاعدة البيانات
#    نفّذ supabase/migrations/0001_init.sql ثم 0002_seed.sql
#    التفاصيل في supabase/README.md

# 4. التشغيل
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000).

### توليد أسرار الجلسات

```bash
openssl rand -base64 48   # لـ SCANNER_SESSION_SECRET
openssl rand -base64 48   # لـ ADMIN_SESSION_SECRET
```

## النشر على Vercel

1. اربط المستودع بمشروع Vercel جديد.
2. أضف نفس متغيرات `.env.example` في **Settings → Environment Variables**.
3. اضبط `NEXT_PUBLIC_SITE_URL` على نطاقك الفعلي.
4. في Supabase، أضف `https://your-domain.com/auth/callback` إلى **Redirect URLs**.
5. في لوحة مُيسّر، أضف ويب-هوك على
   `https://your-domain.com/api/payments/moyasar/webhook` بنفس قيمة
   `MOYASAR_WEBHOOK_SECRET`.

> **ملاحظة:** لوحة المسح تحتاج اتصالاً آمناً (HTTPS) لأن `getUserMedia` لا
> يعمل على HTTP. على `localhost` يعمل استثناءً أثناء التطوير.

## قرارات تصميمية

**الخطوط تُحمَّل قبل الرسم — دائماً.** كل عملية رسم على الكانفس تمر بـ
`ensureFontsLoaded` التي تستدعي `document.fonts.load` صراحةً ثم تنتظر
`document.fonts.ready`. الاعتماد على `fonts.ready` وحده لا يكفي: الخط لا يبدأ
التحميل أصلاً حتى يُستخدم، فيرسم المتصفح بخط بديل. هذا هو سبب مشكلة «الخط لا
يتغير»، ومعالجتها هنا تشمل المعاينة الحية والتوليد النهائي معاً.

**توليد الدعوات في المتصفح.** يوفّر تكلفة الخادم، ويعطي تقدّماً مرئياً
للمستخدم، ويضمن أن الملف النهائي مطابق تماماً للمعاينة لأنه يمر بنفس مسار
الرسم.

**حالة الباركود محسوبة على الخادم.** لا مهام مجدولة ولا اعتماد على ساعة
الجهاز — الحالة تُحسب وقت القراءة من `now()` في قاعدة البيانات.

**كل نص في الموقع بيانات، لا كود.** الصفحات التسويقية تقرأ من `site_content`،
فالأدمن يعدّل أي نص من لوحته مباشرة.

## المراحل القادمة

المخطط والكود مهيّآن لهذه الإضافات دون إعادة هيكلة:

- إرسال الدعوات تلقائياً عبر واتساب/البريد (جدول `guest_deliveries` جاهز)
- دعم اللغة الإنجليزية (كل النصوص مخزّنة كبيانات)
- تقارير إحصائية أعمق
