# قاعدة بيانات بكجات

## تشغيل ملفات الترحيل

### الطريقة الأولى — عبر واجهة Supabase (الأسرع)

1. افتح مشروعك في [Supabase Dashboard](https://supabase.com/dashboard).
2. اذهب إلى **SQL Editor**.
3. انسخ محتوى `migrations/0001_init.sql` كاملاً ونفّذه.
4. كرّر مع `migrations/0002_seed.sql`.

### الطريقة الثانية — عبر Supabase CLI

```bash
npx supabase link --project-ref <project-ref>
npx supabase db push
```

## ترقية حساب إلى أدمن (Super Admin)

بعد إنشاء حسابك من صفحة التسجيل وتفعيل البريد، نفّذ في SQL Editor:

```sql
update public.profiles
set is_super_admin = true
where email = 'your@email.com';
```

ثم افتح `/admin` — ستُطلب منك تهيئة التحقق بخطوتين (TOTP) عبر تطبيق مصادقة
قبل الدخول. هذه الطبقة إلزامية لأن لوحة الأدمن تتحكم بالمنصة كاملة.

## إعدادات المصادقة المطلوبة في Supabase

**Authentication → URL Configuration:**

- **Site URL:** `https://your-domain.com`
- **Redirect URLs:** أضف `https://your-domain.com/auth/callback`
  (وأثناء التطوير: `http://localhost:3000/auth/callback`)

**Authentication → Providers → Email:** فعّل *Confirm email* حتى يُطلب من
المستخدم تفعيل بريده كما هو موصوف في تدفق التسجيل.

## مساحات التخزين

يُنشئ ملف الترحيل ثلاث مساحات عامة تلقائياً:

| المساحة | الاستخدام | من يكتب فيها |
|---|---|---|
| `designs` | تصاميم المستخدمين المرفوعة | كل مستخدم في مجلده فقط |
| `templates` | خلفيات القوالب الجاهزة | الأدمن فقط |
| `gallery` | صور معرض الأعمال | الأدمن فقط |

القراءة عامة في الثلاثة لأن الصور تُعرض في الدعوات والصفحات التسويقية.

## ملاحظات على التصميم

**حالة الباركود محسوبة، غير مخزّنة.** الدالة `guest_code_state` تحسب الحالة
(`inactive` / `active` / `used` / `expired`) وقت القراءة اعتماداً على `now()`
في الخادم. هذا يعني أن التفعيل والانتهاء يحدثان تلقائياً بلا مهام مجدولة، ولا
يمكن التلاعب بهما عبر تغيير ساعة جهاز المسح.

**منع التكرار ذرّي.** الدالة `process_scan` تقفل صف المدعو (`for update`) داخل
معاملة واحدة، فمحاولتان متزامنتان من جهازين مختلفين لا تنجحان معاً أبداً.

**التجاوز اليدوي مسجَّل دائماً.** أي دخول عبر زر «تجاوز» يُكتب في `checkins`
بـ `is_override = true` مع اسم المسؤول ووقت التنفيذ والحالة قبل التجاوز.

## الاستعداد للميزات القادمة

- `guest_deliveries` — جاهز لتسجيل الإرسال التلقائي عبر واتساب/البريد لاحقاً
  دون أي تغيير في المخطط.
- `plans.billing_period` — يدعم `one_time` و`monthly` و`yearly` من البداية.
- `site_content` / `site_settings` — كل نص في الموقع مخزّن كبيانات، فإضافة
  لغة ثانية لاحقاً لا تحتاج تعديل الصفحات.
